Doc FO-STD-001
Audit app v8.1 · setup guide

Read this once, then you're done

Putting the audit app in your auditors' hands

Three set-up jobs, about twenty minutes in total. At the end you have one link to send auditors, and a Google Sheet that fills itself as they finish audits.

What you're building

One link Auditors open it on their phone and add it to their home screen. It becomes a Flame On app icon — no app store, no Google account, nothing to download each time.
Works with no signal The whole audit runs offline. A cold store with no bars is fine — the audit is saved and locked on the phone the moment it's completed.
Audits come to you As soon as the phone has a connection, completed audits send themselves to your Google Sheet. Nobody has to remember to WhatsApp anything.

Your sheet fills itself with

  • ✓Audits — one row per audit: branch, date, score, grade, tier, auto-fail, findings, open corrective actions, auditor, and a link to the full record.
  • ✓Findings — one row for every failed line, with its corrective action, owner, due date and status. This is your chase list.
  • ✓Drive folder — the complete record and the evidence photos, filed by branch.

Part 1 — The Google Sheet that collects audits

About 10 minutes. Do this first — the app needs the link it produces.

1

Make the sheet

Go to sheets.new and name it Flame On — Audit submissions. Don't add any tabs or headings — the script builds those itself.

2

Open the script editor

In that sheet: Extensions → Apps Script. Delete the sample function myFunction() {} that's sitting there.

3

Paste in the receiver

Open apps-script/Code.gs from the app folder, select all of it, copy, paste into the script editor, and save with Ctrl+S.

4

Set your own password phrase

Near the top of the pasted code, change the token to something of your own:

in Code.gs
var SHARED_TOKEN = 'flameon-2026-abbottabad';

Write that phrase down. You'll type the identical text into the app in Part 3.

5

Publish it

Deploy → New deployment. Click the gear beside "Select type" and choose Web app, then set:

  • Description — audit receiver v1
  • Execute as — Me
  • Who has access — Anyone

"Anyone" is not optional

Not "Anyone with a Google account". Your auditors aren't signed in to Google when they submit — if you pick the wrong one, every submission fails.

6

Allow it to reach your sheet

Click Deploy, then Authorize access. Google will warn you the app "isn't verified" — that's because it's your own private script, not a published product. Choose Advanced → Go to Flame On — Audit submissions (unsafe) and continue.

7

Copy the link, then check it

Copy the Web app URL. It ends in /exec. Paste it into a browser — you should see:

what a working receiver replies
{"ok":true,"msg":"Flame On audit receiver is live…"}

Ignore the /dev link

Apps Script also shows a /dev URL. It only works while you are signed in as the owner — an auditor using it gets a login page instead of submitting their audit. Always take the /exec one.

Part 2 — Publishing the app

About 10 minutes. This produces the link you send auditors.

1

Make a GitHub repository

Create a GitHub account if you don't have one, then a new public repository called flameon-audit. Don't tick "Add a README" — the folder already has one.

2

Upload the app folder

The folder is already prepared as a git repository with everything committed. Run these three lines, putting your own GitHub username in the first one:

terminal
cd "C:/Users/huzaifa/Downloads/flameon-audit-app"
git remote add origin https://github.com/YOUR-USERNAME/flameon-audit.git
git branch -M main
git push -u origin main
3

Turn the website on

In the repository on github.com: Settings → Pages. Under "Build and deployment" set Source: Deploy from a branch, Branch: main, folder / (root), and Save.

4

Wait a minute — that's your link

the link you send auditors
https://YOUR-USERNAME.github.io/flameon-audit/

Public repository, public link

Anyone with the address can open the app, which is fine — it ships empty. It contains no audits, no photos, no admin password and no access to your sheet. The one thing that does travel inside it is the submission token, and that token only allows adding audits — never reading or deleting them. Just never commit real audit data or the admin password into this folder.

Part 3 — Connecting the two

The easy way — every auditor set up automatically

Before you push (or edit and push again), open index.html, search for SUBMIT_URL near the top of the script, and fill in the two lines:

in index.html
var SUBMIT_URL="https://script.google.com/macros/s/AKfy…/exec";
var SUBMIT_TOKEN="flameon-2026-abbottabad";

Now every auditor who installs the app is already pointed at head office with nothing to type.

The other way — device by device

Leave those two lines blank, and on each phone go to Admin → Head-office submission, paste the link and token, and press Save. Slower, but the address never appears in a public repository.

Either way, do this once

Press ⇄ Test connection in the Admin panel. It should say ✓ Connected. That's the moment you know the whole chain works.

What to send your auditors

Paste this into WhatsApp, with your real link in place of the placeholder.

message for auditors

Flame On audit app

Open this link on your phone: https://YOUR-USERNAME.github.io/flameon-audit/

Android / Chrome: tap the ⋮ menu → Add to Home screen → Install.
iPhone / Safari: tap the Share button → Add to Home Screen.

A Flame On icon appears on your home screen. Open the audit from that icon from now on.

It works with no internet — do the whole audit offline if the branch has no signal. Completed audits send themselves to head office as soon as you have a connection. The ⇪ button at the top shows anything still waiting.

Your audits are stored on your own phone until they're sent, so please don't clear your browser data, and don't delete the app while audits are still waiting to send.

When you change the app later

Change the cache name every single time

Installed apps keep running their saved copy until the cache name changes. Before you push any edit to index.html, open sw.js and bump the version — v8.1.0 to v8.1.1, and so on. Skip it and your auditors quietly keep filling in the old questionnaire, and you won't find out until the scores look wrong.

the whole update routine
# 1. bump CACHE in sw.js  (v8.1.0 → v8.1.1)
# 2. then:
git add -A
git commit -m "questionnaire update"
git push

Auditors get the new version next time they open the app with a signal. If they have it open already they see a "newer version is ready — Reload now" banner. Their drafts, completed audits and photos are never touched by an update.

If you edit the Google script, re-deploy the right way

Deploy → Manage deployments → the pencil icon → Version: New version → Deploy. This keeps the same address. Creating a new deployment instead gives you a brand new link, and every app already installed on an auditor's phone silently stops submitting.

If something goes wrong

What you seeWhat it means
head office replied 401 or 403The deployment's access isn't set to Anyone. Redo Part 1, step 5.
unexpected reply…You used the /dev link instead of /exec, or the script was never authorized.
token does not match head officeThe phrase in the app and in Code.gs differ. They're case-sensitive.
upload timed outSlow connection carrying photos. It retries by itself; or switch off Include evidence photos in Admin.
The ⇪ number never clearsThat phone can't reach the endpoint at all. Use ⛃ Backup and send the file the old way, then investigate.
An auditor has the old questionnaireYou pushed without bumping CACHE in sw.js. Bump it and push again.
No install prompt on AndroidThe page has to be opened over https:// — GitHub Pages always is — and visited once before Chrome offers it.

Two things worth knowing

Nothing is lost to a bad connection

A completed audit is saved and locked on the phone before any upload is attempted. If the send fails it queues and retries — on reconnect, on next launch, and whenever the auditor taps ⇪ Sync. The ⛃ Backup file still contains everything as the manual fallback. An auditor never waits on the network.

Re-sending is safe

Your sheet keys on the audit's ID, so a re-sent audit corrects its own row rather than appearing twice. Auditors can press Re-send as often as they like.

Unsent audits live on the auditor's phone. Clearing the browser's site data erases them — that's why the message above tells auditors not to. Once an audit reaches your sheet, it's safe regardless.

Where things live. The app folder is Downloads/flameon-audit-app/ — edit index.html there, not the old Downloads/Flame on Audit.html, which is now the frozen previous version. The full written notes are in that folder as README.md and DEPLOY.md, and this page says the same thing in a readable form.
